From a plant observation to a deployed model

The initial deployment uses one enterprise or regional training cell (P2) and one plant (P3). A national service (P1) is a separate recipient when a sharing agreement authorizes a published result.

P3 · Plant

Acquire Read a qualified historian or OPC UA feed into an open62541 adapter. Keep timestamps, units, quality flags and a durable local cursor.

Run locally S11 admits a signed release. S10 serves an expiring A1 advisory and records the operator’s disposition.

P2 · Regional cloud

Prepare and train S05 freezes an authorized snapshot. S06 runs a CubeStudio workflow on Kubernetes and writes evaluation evidence to MLflow.

Publish A project-scoped API stages a model in P2. S07 signs a separate assignment to a named plant.

P1 · National federation

Receive S04 exports an approved product revision through NET-15. S01 checks its grant and issues its own receipt.

Distribute packages S03 indexes approved releases. Each site checks assignment and trust at activation.

P3 → P2
NET-03E exports permitted observations via a DMZ spool. NET-03L delivers observations locally during WAN loss. Each path has its own cursor.
P2 → P3
A site mirror receives the signed bundle and assignment. The plant can verify, reject or recover it using local evidence.
P2 → P1
Only an explicitly granted data product crosses the national boundary. Raw sensor windows and plant control credentials stay within their approved zones.

Scope of “fully open source”. The required application, training, serving and infrastructure software in this design runs on a self-hosted CPU profile. The reference implementation of the English portal, format adapters and site admission services is proposed under Apache-2.0 and still needs to be built. Existing equipment, firmware, certified PLC/DCS/SIS and plant acceptance are external interfaces. Training-data rights and trained weights are recorded separately.

Edition and dependency decisions

  • Community features. Use container-based task templates and inference services. Curate our own recipes and portal. The commercial AIHub marketplace and commercial one-click LLM fine-tuning are outside the required deployment.
  • Queue substitution. The upstream Redis manifest references a Redis 7.4 image. That release line uses source-available licenses. This design selects BSD-licensed Valkey and changes the connection/manifest accordingly. Gate release on enqueue, completion, worker restart, redelivery and deduplication tests.
  • Storage substitution. Configure Ceph RGW for both workflow and MLflow S3 endpoints, and CephFS CSI volumes for shared files. Replace sample storage manifests and test artifact upload, checksum, restore and access revocation across tenants.
  • Reproducible CPU build. Rebuild and mirror dependencies from reviewed sources. Use Debian main on compatible hardware, CPU-only ML libraries, and Grafana OSS. Proprietary GPU stacks, closed FMUs, hosted model APIs and enterprise plug-ins are outside this profile. Pin the selected versions, image digests, licenses, notices, source offers where applicable, owner and support window in the release bill of materials.

The portal is an English-language integration to be implemented on top of CubeStudio. A user selects a task, uploads a dataset, reviews its columns and units, trains, examines held-out results and publishes a project-scoped test endpoint.

Publish a reusable template

The template author supplies a training entry point, input schema, defaults, resource limits and a serving contract. Build a CPU OCI image, test it and push it to Harbor. In the CubeStudio task-template editor, register the image and define the fields and defaults. Release the template and compose validation, training, evaluation and staging as a workflow. Register its version and sample dataset in the portal.

Deploy a trained model

The browser’s Deploy action asks the portal to stage a specific run in the user’s P2 project. Save the preprocessing, model digest, expected input schema and runtime image together. Return a private test page and authenticated prediction API. Expose Stop and previous approved versions. CubeStudio documents creator-level inference deployment. The portal must enforce project-scoped delegated authority and keep a per-user audit trail.

Plant rollout is a separate action. A successful P2 prediction page produces a candidate for review. S07 issues the signed target assignment, the site mirror receives it, and S11 records its independent local admission. Only then can S10 use the model for an A1 advisory. S12 and existing protection systems own plant operating decisions.

English coverage. CubeStudio’s inspected community frontend sets the Ant Design locale to Chinese. The proposed portal owns the English upload form, template inputs, validation errors, result pages and deployment messages. Template authors can use the upstream administration UI. Users running a published template need only a browser and their project account.

Consistent method and decision rules

  1. Identity: resolve the upstream repository and label mirrors, suite/core scope and non-GitHub upstreams. Missing star counts remain “not applicable/unverified,” never zero.
  2. Activity: inspect the default-branch commit and release evidence separately. Repository pushed_at may reflect any branch; updated_at may reflect metadata and is not used as a code-maintenance metric. A recent timestamp alone does not establish substantive engineering, support or response quality.
  3. Release: show the observed release/tag evidence and explicitly labeled publication or feed-update timestamp where available. Do not infer initial publication from an Atom update, or treat this as the selected deployment version. GitHub “latest” semantics, release feeds and upstream package channels differ; stable supported maintenance branches must be selected independently.
  4. Decision: no new deployment from an archived or explicitly retired upstream without an approved maintained replacement/fork. Active evidence permits evaluation, not approval. Missing evidence triggers verification, not an “inactive” label. Production selection additionally requires license/SBOM, supported-version policy, security response, operator staffing, compatibility, recovery and site acceptance.
